# Bain-AC — 전략 패널

멀티에이전트 전략 패널. 시장조사 리포트를 넣으면, 사실검증을 거친 다각도 리뷰와 하나의 방어 가능한 권고를 돌려준다.

MBB 엔게이지먼트 팀 구조를 따르는 10개 에이전트로 구성된다 — 검증된 사실 베이스를 소유하는 리서치 데스크, 리포트를 독립적으로 읽는 7개 실무 렌즈, 그들의 작업을 공격하는 레드팀, 그리고 결정하는 파트너.

> English: [`README.md`](README.md)

## 실행 방법

두 가지 런타임을 지원한다. 같은 에이전트 정의를 공유한다.

**1. Python CLI** — 헤드리스, 스케줄러/CI용

```bash
pip install -e ".[dev]"

panel run inbox/report.pdf --lang ko    # 한국어 보고서 생성
panel run inbox/report.pdf --dry-run    # 비용 없이 실행 계획만 확인
panel roster                            # 로드된 에이전트와 단계 그래프
panel qc reports/2026-08-16-report      # 완료된 라운드 재검사
```

**2. Claude Code 대화형**

```
/panel inbox/report.pdf
```

출력은 `reports/YYYY-MM-DD-<슬러그>/`에 생성된다. 최종 산출물은 `04-partner-synthesis.md`이고, 나머지는 그 근거가 되는 감사 추적이다.

## 최초 설정

1. **`context/00-core-brief.md`를 채운다.** 모든 에이전트가 매 라운드 읽는다. 템플릿을 지우고 2쪽 분량으로 작성.
2. **컨텍스트 파일 추가** — `context/*/` 아래에 넣고 `context/INDEX.md`에 등록. 가진 것부터 시작하면 되고, 채워질수록 판단이 날카로워진다.
3. **`docs/ko/HOUSE-STANDARD.md`를 읽는다.** 에이전트들이 따르는 증거 계약이며, 산출물을 평가할 기준이다.

컨텍스트가 비어 있어도 실행은 되지만, 그러면 렌즈들이 회사 맥락 없이 입력 리포트만 보고 판단한다. CLI가 이 경우 경고한다.

## 작동 방식

```
리포트 → 사실 베이스 → 7개 렌즈(병렬·상호 비공개) → 레드팀 → 파트너 종합
```

설계의 핵심은 세 가지다.

- **사실 베이스가 모든 것을 막는다.** 주장이 검증·등급화되기 전에는 어떤 렌즈도 돌지 않는다. 빈칸을 메우려고 숫자를 지어낼 필요가 없어진다.
- **렌즈들은 서로를 보지 못한다.** 병렬로 디스패치되므로 다른 렌즈의 결론에 앵커링될 수 없다. 이들의 **의견 충돌이 곧 산출물**이다.
- **공격과 결정이 분리된다.** 레드팀이 공격하고 파트너가 결정한다. 방금 작업을 공격한 에이전트는 그 결론을 옹호하기에 부적절하다.

상세 근거: [`docs/ko/ARCHITECTURE.md`](docs/ko/ARCHITECTURE.md)

## 증거 규칙

맨숫자 금지. 모든 정량적 주장은 출처를 밝히는 태그를 단다.

| 태그 | 의미 |
|---|---|
| `[F-012]` | 검증됨 — 사실 베이스에 출처·URL·접근일·원문 인용 존재 |
| `[R-p14]` | 리포트 14쪽 주장. **검증 안 됨.** |
| `[C-finance/unit-econ.md]` | 내부 컨텍스트 팩 |
| `[EST: 방법]` | 추정 — 재현 가능한 도출 과정 포함 |
| `[ASSUMPTION]` | 근거 없이 채택한 전제 |

`[F-]`와 `[R-]`의 구분이 핵심이다. 하나는 누가 확인했다는 뜻이고, 다른 하나는 리포트가 그렇게 말했다는 뜻일 뿐이다. `[R-]`에 기댄 권고는 숨기지 않고 표시한다.

이 규칙은 5단계에서 **정규식으로 기계 검사**된다 — LLM의 판단이 아니라 결정론적 코드다.

## 디렉터리 구조

```
.claude/agents/       10개 에이전트 정의 — 로스터를 바꾸려면 여기를 편집
.claude/skills/panel/ /panel 오케스트레이터 (Claude Code용)
panel/                Python 런타임 — 파이프라인, 로더, QC 검증기
tests/                40개 테스트 (pytest)
context/              오프라인 컨텍스트 팩. INDEX.md가 매니페스트
docs/                 영문 문서
docs/ko/              한글 문서
inbox/                신규 리포트를 여기에 넣는다
reports/              라운드 산출물
```

**`.claude/` 안의 마크다운은 실행되는 정의**다 — YAML frontmatter가 모델·도구 권한을 강제한다. 그 밖의 마크다운은 문서다.

## 비용

전체 라운드 약 **$7**, 변동 없는 주의 델타 리뷰 약 **$1.50**. 렌즈는 Sonnet 5, 리서치 데스크·레드팀·파트너는 Opus 5로 돈다 — `.claude/agents/*.md`의 `model:` 한 줄로 바꿀 수 있고, `--budget`으로 에이전트당 상한을 건다.

이 수치는 이 시스템 자체 기준으로 `[EST]`다. 세 라운드 돌린 뒤 실측치로 교체할 것.

## 주간 실행

새 리포트가 없으면 `/panel`은 **델타 리뷰**를 돈다: 직전 종합의 트리거가 발동했는지만 확인하고, 아무것도 안 바뀌었으면 그렇게 보고하고 멈춘다.

일정을 정당화하려고 발견을 만들어내는 패널은 한 달 안에 아무도 읽지 않게 된다. 조용한 주는 실제로 조용해야 한다.

## 개발

```bash
python3 -m pytest tests/ -q     # 40 passed
```

QC 검증기(`panel/verify.py`)는 순수 함수로 작성되어 있고 모델 호출이 없다. 증거 계약 검사가 LLM 판단에 의존하면, 그것이 막으려는 실패 양상을 그대로 물려받기 때문이다.
